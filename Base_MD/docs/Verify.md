# Verification

실행하지 않은 검증은 완료로 표시하지 않습니다.

## M0 문서 검증

문서 링크, 단계 선행 조건, 소유권과 패스 책임의 일관성을 확인합니다.
계획 폴더와 실제 폴더, 확정과 제안, 구현과 검증 상태를 구분합니다.

## M1 빌드

- MSVC v145와 Windows SDK 설치를 확인합니다.
- Debug / x64와 Release / x64를 빌드합니다.
- 셰이더 경로가 실행 작업 디렉터리에 의존하지 않는지 확인합니다.
- 실패 시 명령, 오류와 누락된 도구를 기록합니다.

## M1 실행과 수명

- [ ] 창, 배경, 정점 색상 삼각형이 실제로 표시된다.
- [ ] 여러 프레임 동안 깜박임이나 GPU 오류가 없다.
- [ ] 가로 / 세로 resize에 정상 대응한다.
- [ ] 최소화 후 복원하면 다시 출력한다.
- [ ] Device 생성 전 Debug Layer를 활성화하고 오류 / 손상 메시지가 없다.
- [ ] Fence 완료 전에 allocator / 리소스를 재사용하지 않는다.
- [ ] 백버퍼 PRESENT / RENDER_TARGET 상태가 일관된다.
- [ ] 정상 종료와 초기화 실패에서 자원을 정리한다.

Debug Layer 사용 불가 시 원인과 미검증 상태를 기록합니다.
빌드 성공만으로 화면이나 GPU 수명 검증을 통과했다고 판단하지 않습니다.

## 이후 회귀

M2: Component 책임, 깊이, 카메라 / Transform 규약.
M5: 동일 불투명 장면의 Forward / Deferred 결과, 투명 합성,
resize 후 G-buffer, GPU 오류와 GPU 시간 비교.

## 결과 형식

날짜, 빌드 구성, OS / GPU, 도구 버전, 실행 명령, 통과 / 실패 / 미실행,
화면 증거와 남은 문제를 보고합니다. 현재 M1은 전부 미실행입니다.
